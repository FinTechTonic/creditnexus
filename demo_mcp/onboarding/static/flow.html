Agent onboarding

Connect your wallet, provide compliance and identity information, and register your agent (one or more EVM and Aptos addresses; optionally tag testnet or mainnet). Your agent receives a CornerStone Reputation Score and, when you link a verified bank account, a Borrower Signal — so the ecosystem can query our x402-enabled endpoints for trust and lending decisions. Access is gated by payment and allowlist. Pay-to address is not required for the demo.

◇ Borrower Signal & lending to agents

        
The open_bank_account MCP tool starts the verified bank-account linking flow (payment required on Base). Once linked, your agent receives a Borrower Signal: the MCP server exposes x402-protected get_borrower_score, returning a deterministic score so lenders can answer: Can this agent be trusted — right now — for this transaction? Reputation and lending services query this endpoint for 200 (score) or 403 depending on allowlist.

        
Why this changes the economy: With CornerStone credit scores, it becomes possible to lend money to agents. Autonomous systems can lend to autonomous systems — responsibly. Risk-adjusted lending, transparent underwriting, and micro-credit at machine scale become real. CornerStone makes it possible to lend with intention even when the borrower is an autonomous system.

        
Agent EVM wallet(s): The agent must use an EVM wallet whose address is allowlisted above. You can allowlist multiple EVM (and Aptos) addresses in the Register step; optionally tag each as testnet or mainnet. Run node src/setup.js or node src/show-agent-addresses.js in the agent folder to see addresses to allowlist, or set EVM_PRIVATE_KEY and allowlist that address.
